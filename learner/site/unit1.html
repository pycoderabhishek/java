Detailed Theory (Exam-Oriented)

Java is a platform-independent, object-oriented programming language developed by Sun Microsystems. Its key strength is the Java Virtual Machine (JVM), which executes platform-neutral bytecode. A Java program is first compiled by the Java compiler into bytecode (.class file). The JVM then loads, verifies, and executes this bytecode on any operating system with a JVM, ensuring "Write Once, Run Anywhere".

Java architecture includes the JDK (development tools + JRE), JRE (JVM + core libraries), and JVM (runtime engine). Variables in Java must be declared with a type, and the scope and lifetime depend on where they are declared (local, instance, or static). Command-line arguments allow inputs at runtime and are accessed via the `main` method parameters.

Definitions & Explanations

JVM
The runtime engine that loads, verifies, and executes Java bytecode.
JRE
The JVM plus core libraries required to run Java applications.
JDK
The JRE plus development tools like `javac`, `javadoc`, and debugger.
Bytecode
Platform-neutral intermediate code produced by the Java compiler.
Scope
The region of a program where a variable is accessible.
Command-line Arguments
Input values passed to the program at runtime via the command line.

Code Examples

Simple: Hello World + Command-Line Args

class Hello {
  public static void main(String[] args) {
    System.out.println("Hello, Java!");
    if (args.length > 0) {
      System.out.println("First arg: " + args[0]);
    }
  }
}
// Compile: javac Hello.java
// Run: java Hello Alice

Advanced: Variable Scope

class ScopeDemo {
  static int global = 10;     // static scope

  public static void main(String[] args) {
    int local = 5;            // local scope
    if (local < global) {
      int block = 2;          // block scope
      System.out.println(global + local + block);
    }
  }
}

Key Points for Revision

  • Java is compiled to bytecode and executed by the JVM.
  • JDK = JRE + tools; JRE = JVM + libraries.
  • Variables have type, scope, and lifetime.
  • Command-line arguments are accessed through `main(String[] args)`.
  • Platform independence is achieved via JVM.

Practical Section

Program: Sum of Two Numbers (Command-Line Args)

class SumArgs {
  public static void main(String[] args) {
    int a = Integer.parseInt(args[0]);
    int b = Integer.parseInt(args[1]);
    System.out.println("Sum = " + (a + b));
  }
}
// Run: java SumArgs 5 7
Output: Sum = 12

Step-by-step Explanation

  1. Read inputs from `args` array.
  2. Convert to integers using `Integer.parseInt()`.
  3. Add values and print the result.

Question Bank

5 Marks Questions

  1. Define JVM and list its main components.
    JVM is the runtime engine that executes bytecode. Components: Class Loader, Runtime Data Areas (method area, heap, stack, PC register, native stack), Execution Engine (interpreter, JIT, GC), and JNI.
  2. Differentiate JDK, JRE, and JVM.
    JVM executes bytecode. JRE = JVM + core libraries. JDK = JRE + development tools like `javac` and `javadoc`.

8–10 Marks Questions

  1. Explain the Java compilation and execution process with bytecode.
    Source code is compiled by `javac` into bytecode (.class). The Class Loader loads classes, Bytecode Verifier checks safety, and the Execution Engine interprets or JIT-compiles bytecode to native code, enabling platform independence.
  2. Discuss Java data types and variable scope with examples.
    Java has primitive types (int, char, float, etc.) and reference types. Variables can be local (method/block), instance (per object), or static (class-level). Scope defines visibility; lifetime depends on where declared.

15 Marks Long Question

Describe JVM architecture in detail and explain how it supports platform independence.
JVM architecture includes the Class Loader subsystem, Runtime Data Areas (method area, heap, stack, PC register, native method stack), Execution Engine (interpreter, JIT compiler, GC), and JNI for native calls. Java source is compiled into bytecode, which is platform-neutral. The JVM on each OS interprets/JIT-compiles bytecode into native instructions, ensuring Write Once Run Anywhere. The verifier ensures security, while GC manages memory, making Java robust and portable.
